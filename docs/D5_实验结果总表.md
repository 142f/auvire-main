## 6. 结论

1. **排序是主要瓶颈**：同一套提案，oracle 排序把 AP@0.95 从 83.15→92.75（3k）/ 83.41→93.33（全量）。
2. **质量读出头能吃到的只是零头**：+0.91pp（全量，最好头）/ +0.56pp（4 头均值），而天花板是 +9.9pp。
3. **被否定的设计**：联合训练（扰动主干）、近失对排序项（+0.49 < +0.78）、多头 logit 集成（+0.15）、二值目标（3k 好但全量更差）。
4. 下一轮方向（按性价比）：(a) 让质量头**看到段级上下文**（当前只有 k=3 的局部卷积，判"框准不准"需要整段证据）；(b) 用 **soft-NMS 后的段级聚合特征**训练质量头；(c) 把 IoU 目标换成"段内相对序"。
## 7. 第三轮：头的容量/上下文变体（3k，ΔAP@0.95，基线 83.148）

| 设计 | 头 | Δ | 均值 |
|---|---|---|---|
| 局部（k=3）+ 偏移输入 | f_a / h2 / h3 / hb | +0.78 / −0.07 / +0.62 / +0.90 | **+0.56** |
| + 膨胀卷积（d=6，RF≈37 帧） | d1 / d2 | +0.23 / +0.36 | +0.30 |
| + 框内均值池化（段级证据，130→258 通道） | p1 / p2 / p3 | +0.10 / +0.44 / +0.36 | +0.30 |

| 设计 | dev（α=0.8） | dev 头间 std |
|---|---|---|
| 基线（无头） | 81.89 | — |
| 局部 | 82.21 / 82.86 / 83.06 / 82.90 | 0.35 |
| 膨胀 | 82.55 / 82.66 / 82.60 | **0.05** |
| 池化 | 82.64 / 82.85 / 82.82 | 0.09 |

**结论（强证据）**：
1. **上下文不是瓶颈**：膨胀卷积把 RF 从 3 帧扩到 ~37 帧、池化把"段级证据"直接喂进头，**3k 增益反而从 +0.56 降到 +0.30**。
2. 上下文把**头间方差**从 0.35 压到 0.05–0.09 → 变体的稳定性提升是真的，但**均值没有提升**。
3. 因此 MAQS 的真实效应量是 **+0.5 ± 0.4pp**（10 个头的分布），全量 test 的 +0.91 位于该分布的乐观尾部。
4. 与 oracle（全量 **+9.92pp**）相比只兑现 5%，**+1.0pp 验收线在本机制下不成立**。
## 8. 第四轮：几何/宽度假设（否证）

排序归因显示：召回 0.8→0.9 时多消耗 1047 个提案只换 84 个 TP，其中 737 个是"假视频内 IoU≤0.5 的框"。第一假设是**回归输出的框太离谱（超宽/超窄）**。

做法：解码时按预测段长（帧）过滤，只保留落在区间内的提案（`AUVIRE_WIDTH_RANGE`，只读诊断）。

| 宽度区间（帧） | AP@0.5 | AP@0.75 | AP@0.95 | 与基线差 |
|---|---|---|---|---|
| 不过滤（基线） | 98.709 | 95.838 | 83.148 | — |
| [2, 40] | 98.709 | 95.838 | 83.147 | **−0.001** |
| [2, 60] | 98.709 | 95.838 | 83.147 | **−0.001** |

**结论：几何假设被否证。** 那 737 个 FP 的框长都落在 2–40 帧（LAV-DF 的真实段长范围）内，不是"框爆炸"，而是**位置错**——模型在不属于 GT 段的帧上以合理长度开火。这属于**特征信息不足**（那些帧看起来就是假的），不是打分或几何能修的。
